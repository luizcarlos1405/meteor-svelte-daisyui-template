# AGENTS.md

Compact guide for OpenCode sessions working in this repo. Read `SPEC.md`
(architecture/conventions/decisions) for full context.

## Commands

- **Dev server:** `meteor` (or `npm start`).
- **Full test suite:** `npm test` — runs `meteor test` (meteortesting:mocha) on **port 3100** (keeps the dev port free).
- **Pure unit tests only (fast, ~20ms, no Meteor boot):** `npx mocha --import=tsx './imports/api/**/*.test.ts'`.
- **Typecheck:** `npm run typecheck` — uses **svelte-check**, not `tsc`.
- **Lint:** `npm run lint`. **Format:** `npx prettier --write .`.

### Pre-commit gate (lefthook.yml, sequential)

prettier → eslint → typecheck → unit tests. All must pass to commit (~8s).

- **In lefthook, invoke tools directly with `npx`/`npm run`, never `npm test`** — lefthook's context resolves the wrong `package.json` and reports "Missing script".
- The gate runs only the pure unit tests (mocha+tsx); the full `npm test` (Meteor integration) is **not** in the gate.

## Architecture

Functional Core + Imperative Shell (SPEC §3):

- **`imports/api/core/`** — pure TS (no `meteor/*`, no DB, no I/O, no `Date.now()`/`Math.random()` unless injected). The **only** place business rules live. Unit-tested.
- **Shell** — `imports/api/methods/` (`jam:method`, isomorphic RPC), `imports/api/publications/` (server reads), `imports/ui/stores/` (client: subscribe + Minimongo read; **no business logic**).
- **Entrypoints:** `client/main.js`, `server/main.js`. **Import order matters** — see toolchain below.
- Imports use absolute paths with a leading `/` (tsconfig maps `/*` → `./*`); `meteor/*` resolves to `zodern:types` (`/.meteor/local/types/packages.d.ts`, regenerated by a meteor build).

## Toolchain quirks (Meteor 3 + Rspack + Svelte 5)

- **SWC doesn't parse `.ts` as TypeScript by default** here — fixed in `rspack.config.js` via `Meteor.extendSwcConfig({ jsc: { parser: { syntax: 'typescript' } } })`. Every plain `.ts` file relies on this.
- **Tailwind v4 + DaisyUI 5** wired through a `postcss-loader` rule + `postcss.config.js` (`@tailwindcss/postcss`). Uses daisyUI's stock `light`/`dark` themes (light default, dark via `prefers-color-scheme`) — no custom theme, no custom color tokens. Use daisyUI semantic classes only: `text-base-content/60` for muted text, `text-base-content/40` for tertiary, `bg-error/10` / `bg-primary/10` for soft tints, `border-base-300` for dividers. Never hand-rolled color utilities.
- **`lucide-svelte`** ships extensionless internal imports → needs `resolve: { fullySpecified: false }` on `/\.m?js$/` (already in rspack config).
- **svelte-preprocess uses `typesCheck: false`** — build-time TS diagnostics crash it. Use `npm run typecheck` (svelte-check) for type errors.
- **`rspack.config.js` edits require a full `meteor` restart** (HMR doesn't reload it). Clear `node_modules/.cache/rspack` if you see stale errors after a config change.

## Svelte 5 + stores

- **Runes (`$state`/`$derived`/`$effect`/`$props`) only inside `.svelte` files.** Shared `.ts` modules under `imports/ui/stores/` are processed by SWC (not the Svelte compiler), so runes wouldn't transform — use classic `writable` from `svelte/store` there (see `auth.ts`, `connection.ts`).
- Reactive Meteor data (auth, connection status, sync) is tracked via `Tracker.autorun` writing into a `writable` store.
- Routing: **svelte-spa-router v5** — navigate with `push(path)`; read location off the `router` object (`router.location`, `router.params`). There is **no** `location` store export. Named route params are typed `Record<string,string> | undefined`.

## Testing quirks

- **Integration tests that need the Meteor runtime live in `tests/*.test.ts`, NOT `imports/api/**/*.test.ts`.** The lefthook unit gate runs `mocha --import=tsx` without a Meteor runtime and fails on any `import { Meteor }`. Pure core tests go in `imports/api/core/*.test.ts`.
- In `assert.rejects` validators, **duck-type the error** (`(err as { error?: string }).error === 'notAuthorized'`) — `instanceof Meteor.Error` is unreliable (dual-package instance).

## Methods (jam:method) conventions

- `createMethod({ name, schema, run })` with a Zod schema. Defaults: `returnStubValue: true`, `throwStubExceptions: true` — **an isomorphic client stub that throws aborts the authoritative server call.** Gate every DB-backed permission/not-found throw behind `if (Meteor.isServer)` so the optimistic stub never aborts the server.
- Test a method directly via `method.call({ userId }, args)` (bypasses the wire; runs validation+pipeline with a mocked invocation).
- `Random.id` loses its `this` when passed bare — wrap as `() => Random.id()`.
- Insert methods **must return the new `_id`** (offline replay correlation).

## Offline (jam:offline)

- `imports/api/offline/config.ts` (`Offline.configure`) must be imported **before** the collections barrel — jam:offline's `Mongo.Collection` constructor override snapshots `Offline.config` at construction time. `.keep()` is monkeypatched at runtime and absent from TS types → cast narrowly: `(Things as unknown as { keep: (f: unknown) => void }).keep(...)`.
- `isSyncing` is exported by the **client build only**; only import it from client-only modules (e.g. stores reached via `.svelte`).
- PWA (service worker, manifest, icon) is hand-rolled under `public/`. Bump the `CACHE` key in `public/sw.js` when shipping breaking shell changes.

## Style conventions

- **Code/identifiers/schemas/method-names/error-codes in English; user-facing strings default to English** (swap per project if you need another locale — they live in the `.svelte` components and `accountsEmail.ts`).
- **Async DB only** — always the `*Async` variants (`insertAsync`, `findOneAsync`, …). On the server in Meteor 3, `findOne()` is disabled in publish handlers — use `findOneAsync()`.
- Types derive from Zod via `z.infer` wherever a schema exists; don't hand-write duplicate interfaces.
- Soft-delete everywhere ("remove" = soft-delete; publications exclude `deleted:true`). On the server, `findOneAsync`/`find()` auto-filter via jam:soft-delete's `autoFilter`.
- **jam:soft-delete's `overrideRemove` applies to every collection, including `Meteor.users`.** Plain `removeAsync({})` soft-deletes (doc keeps its `_id`). To hard-remove in test fixtures (needed for fixed-`_id` inserts to avoid E11000), pass `{ forever: true } as unknown as Parameters<(typeof Coll)['removeAsync']>[1]`.
- No comments unless explicitly requested.

## Design

No component kit ships with the template — pages use daisyUI classes directly. The theme tokens are in `client/main.css` (mapped to DaisyUI theme + Tailwind `@theme`).
